# Historical burn-in: May 2026

**Reported run:** 2026-05-09 through 2026-05-12  
**System:** REPRAM, two Go nodes and one TypeScript node, default enclave,
HTTP port 18080  
**Workload:** k6 `workload.js`, driven through the segmented runner

This report preserves observations from the pre-Sopholeth mixed
implementation. It is not a current deployment guide or public launch
qualification. The TypeScript node was subsequently removed and its
WebSocket tree was restored in Go; that Go tree still needs its own sustained
validation.

The original report described public-mode configuration in a private lab.
It did not establish a live public mesh. The recorded timeline includes a
driver pause, TS rebuilds, and a shortened final segment, so it should not
be read as 72 uninterrupted hours of fixed-version mixed-cluster load.

## Recorded node snapshots

| Node | Lab host | Implementation | Reported final uptime | Heap | Other memory |
| --- | --- | --- | --- | --- | --- |
| node-a | 10.0.20.72 | Go | 72h47m | 26.0 MB | 143 MB runtime system memory |
| node-b | 10.0.10.81 | Go | 72h41m | 37.3 MB | 143 MB runtime system memory |
| node-c | 10.0.10.104 | TypeScript | 37h18m | 46.2 MB | 201 MB RSS |

The original observations reported no Go restarts and bounded Go heap over
the run. Node-a recorded `num_gc=75361` and cumulative
`total_alloc=1.45 TB`. These describe runtime activity, not client throughput.

Node-c's shorter uptime followed three rebuilds. The final restart applied
the self-attachment fix on May 10. Later observations placed its RSS around
191–201 MB. The gap between managed heap and RSS was one reason to investigate
the cost of the embedded runtime; those numbers alone do not identify every
source of overhead or rule out leaks.

## Defects and follow-up changes

| Reference | Observation or change |
| --- | --- |
| #94, #117 | TS response handling and connection reuse; moved from fetch/undici to per-peer HTTP agents. |
| #116, PR #118 | Serialized TS broadcast replaced with parallel fanout. |
| PR #119 | Per-peer socket limit adjustment. |
| #120, PR #121 | TS self-attachment caused unconfirmed local writes; self-skip added. |
| #122, #123, PR #125 | Runtime footprint work led to Go-native MCP and retirement of the TS node. |
| #133, #135 | Removing TS exposed the missing Go tree; the Go port subsequently restored it. |

The observer reported that gossip, peer HMAC, and quorum messaging
interoperated between implementations during the run. This is useful
interoperability evidence, not exhaustive wire conformance or a proof that all
failure paths return the expected status.

## Evidence limits

The load driver's logs and summaries were not captured with this report.
Consequently:

- Request throughput and latency cannot be reconstructed from the allocation
  totals.
- Periodic status checks cannot establish an HTTP 5xx rate.
- The report does not demonstrate correctness under partitions, duplicated
  acknowledgements, or adversarial wire input.
- It does not validate the later all-Go multi-substrate/transient tree.
- It does not validate production signed discovery, the public trust anchor,
  or DNS cutover.

The [April artifact directory](../archive-2026-04-25/) belongs to a separate
earlier run and should not be cited as raw evidence for these May snapshots.
